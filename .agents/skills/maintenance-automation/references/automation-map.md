# Maintenance authority map

Use this routing table before adding automation. The paths and commands point
to the current owner; they do not make every listed repair safe to run against
remote state.

| Concern | Committed authority | Read-only or focused check | Repair or projection boundary |
| --- | --- | --- | --- |
| Dependency proposals and lockfile refresh | `renovate.json`, package and language lockfiles | `npm run validate:policy` plus the affected language tests | Renovate opens bounded review proposals; it does not automerge |
| Local validation scope | Root and nested `AGENTS.md`; decision 0088 | Inspect staged, unstaged and relevant untracked changes; use existing impact ownership and affected downstream consumers, unioning mixed scopes | Unknown, unsafe or shared-authority scope requires full local validation. Complete integration, merge, release and publication gates remain required. Evidence reuse requires unchanged tested inputs and fresh affected-scope checks, never an old exact-tree full-pass claim. |
| CI lane selection | `.github/ci-impact.json` and `tooling/internal/ciplan/` | `go -C tooling run ./cmd/20w ci plan --root .. --base <commit> --head <commit>` with exact lowercase 40-character hashes | Committed merge-base comparison only, not working-tree scope or Go package selection. `.github/workflows/ci.yml` runs the projected lanes; `--full` remains the integration escape hatch. |
| Labels, roadmap milestones, issue assignments, item status lifecycle and linked pull-request metadata | `.github/labels.json`, `.github/milestones.json`, `.github/issue-milestones.json`, the managed issue's classifications and one explicit pull-request body reference | `go -C tooling run ./cmd/20w github sync-metadata --root .. --check` and `go -C tooling run ./cmd/20w github sync-pr-metadata --root .. --check` | Trusted-main workflows or explicit repository commands; issue events and full sync repair bounded issue drift, while pull-request events plus bounded managed-status and open-PR discovery reuse the one-reference projection or closed cleanup. Preserve unrelated metadata, make missing or competing references a no-write result and never infer `status:wontfix`; a closed pull request with only an unknown status still needs its event or explicit number. |
| Experiment manifests and release candidates | `experiments/workstation/manifests/` and experiment contracts | `go -C tooling run ./cmd/20w experiment validate --root ..` and `go -C tooling run ./cmd/20w experiment release-plan --root ..` | Release workflow packages only admitted, exact-source artifacts |
| PDF publication | canonical book sources, `tooling/pdf-renderer/`, and renderer lock | `go -C tooling run ./cmd/20w publication render-pdf --root .. --check` and `npm run validate:book-pdf` | `npm run generate:book-pdf`; generated reader copies remain non-authoritative |
| Book support provenance | `scripts/book-support-sources.json` and the protected parser in `scripts/book-source.mjs`; decision 0076 | `node --test scripts/book-route.test.mjs` and `npm run validate:book-pdf` | The exact inventory selects release and site checks, unioned with other changed-path owners. Its bytes and selected source bytes remain digest-bound; changed provenance still requires fresh PDF and semantic bindings. Parser, strict JSON helper and selector edits retain full and renderer gates. Remove the narrow owner if inventory data gains executable authority or the isolated dependency boundary changes. |
| PDF renderer reproducibility | renderer-lock schema 3, the renderer predicate and proof projection in `tooling/internal/ciplan/`, and `tooling/internal/pdfrender/`; decisions 0077 and 0078 | Focused Go planner, renderer and CLI tests plus workflow policy tests | Both proof scopes compare two isolated renders. Optional `--cache-dir build/cache/pdf-renderer` requires `--ref main`; cache-enabled receipts use schema 6 and retain actual proof/build/render counts and cache identity. A warm render-pair imports inspected BuildKit cache by manifest digest in a new locked builder and checks image, original manifest and config identities before rendering; a cold pair builds once without cache. Image-build proofs never import cache and retain two fresh no-cache builds; the first may export a seed. Cache placement requires a passing comparison, retained receipt and owned-image cleanup; cancellation prevents placement. Defaults and tagged releases remain cache-free (schemas 5 and 4 retain their existing scope meanings). Hosted cache saves are restricted to successful main pushes; PRs may restore but not save, with exact keys and no fallback keys. These are configured boundaries, not proof of a live hosted restore. CI keeps proof evidence for 30 days. Deleted presentation authority still expands to full. Cache reuse establishes neither admitted image acquisition nor a measured power gain. |
| PDF semantic tools image | `tooling/pdf-tools/`, decision 0053 and the explicit `go-pdf-tools` impact rule | `go -C tooling run ./cmd/20w publication verify-pdf-tools --root ..` | The impact rule selects only Go and release checks until a focused final-image gate exists. The local reproducer can prepare explicit `NO_RESULT` candidate files after its two-build check; publication and digest admission remain maintainer-gated issue-20 work. Package revisions still require review and a fresh lock. Do not schedule a lock refresh or use an ambient Poppler fallback. |
| Reader artifacts and Pages | `github-pages/public-artifacts.json`, canonical Markdown, and Pages source | `npm run test:github-pages` | `npm run prepare:reader-artifacts` and the trusted Pages workflow |
| Public redirect and certificate drift | `.github/public-transport.json` and decision 0047 | `go -C tooling run ./cmd/20w publication verify-public-transport --root .. --check` | The post-deployment Pages job performs the bounded live check; DNS and Cloudflare settings remain administrative state |
| Field coverage and test coverage | research ledgers, experiment contracts, and generator source | `npm run validate:coverage` and `npm run check:test-coverage` | `npm run generate:coverage` or `npm run audit:tests` only after reviewing the source delta |
| Scientific taxonomies | pinned taxonomy sources and import rules | `npm run validate:taxonomies` | `npm run generate:taxonomies`; imported terms do not become evidence |
| Translation freshness | English canonical files and `translations/manifest.json` | `npm run validate:translations` | Candidate export/import remains review-only; named human review is required for publication |
| Prose tripwires | canonical project Markdown and `scripts/audit-prose-style.mjs` | `npm run check:prose` | Conservative edits use `research-writing` and `reader-editor`; never auto-paraphrase claims |
| Repository policy and security posture | `AGENTS.md`, `docs/principles.md`, pinned workflows, and security configuration | `npm run validate:policy`, CodeQL, Scorecard, and dependency review | Repair the owned source; never silence a finding merely to make a gate green |
| Release state and assets | exact Git tag, release workflows, checksums, and Go release packages | The `go -C tooling run ./cmd/20w release` inspection and validation subcommands | The release workflow mutates only the exact admitted tag and release identity |

When two rows appear to own the same value, fix that duplication before adding
a synchroniser. Generated state should point back to its authority and expose a
freshness check.
