## Pre-release evidence and publication conditions

Publication requires the aggregate gate, an observed-complete deterministic
tag-bound PDF, checksum and attestation verification, and offline execution of
every admitted OCI digest to pass on the exact tag. The release workflow must
record the tag, commit, run identity, PDF digest and observed diagram count,
asset checksums and final OCI digests. This source disclosure does not claim
that those post-tag checks have completed, or that the three first-use GHCR
packages under `ghcr.io/cordanallm/` are public until unauthenticated
exact-digest pulls pass.

Known limits carried into this snapshot:

- the tracked semantic baseline's Poppler captures were not re-captured for
  the renders after `v0.3.0`, because the digest-pinned PDF-tools image is not
  yet published ([#20](https://github.com/cordanaLLM/20-watts-was-enough/issues/20));
  only the identity fields moved with each re-render;
- the PDF's tag structure and reading order are incomplete
  ([#17](https://github.com/cordanaLLM/20-watts-was-enough/issues/17)), so no
  accessibility conformance is claimed;
- an intermittent footer-only terminal page can make a render pair differ
  ([#122](https://github.com/cordanaLLM/20-watts-was-enough/issues/122)); a
  release run that hits it is re-run on the same tag, never on a moved tag.

These checks establish a reproducible publication boundary. They do not create
a scientific result or an independent review.

## Correction to the v0.3.0 disclosure

- **Error:** the [`v0.3.0` disclosure](v0.3.0.md) states that accountable
  publication approval "is evidenced only by the successful
  maintainer-controlled release workflow and resulting GitHub Release". The
  `v0.3.0` release workflow did not succeed: run
  [33326379738](https://github.com/cordanaLLM/20-watts-was-enough/actions/runs/33326379738)
  failed at "Publish or validate the immutable GitHub release". The workflow
  had created the release as a draft at 2026-08-30T17:50:32Z; it was published
  at 2026-08-30T19:00:33Z outside any workflow run, and the release API does
  not record who published it.
- **Discovered:** 2026-09-28, during the post-transfer release review.
- **Scope:** the approval evidence of the `v0.3.0` snapshot only. The tag, the
  published assets and their immutability (read back as immutable on
  2026-09-30) are unchanged, and no claim, status, source, protocol or result
  depended on that sentence.
- **Consequence:** conclusions do not change. The `v0.3.0` approval rests on
  the maintainer's manual publication of the workflow-created draft, not on a
  successful workflow run. The `v0.3.0` record is preserved unchanged apart
  from a dated pointer to this correction. The release draft-state handling
  in `tooling/internal/releasecheck` changed after `v0.3.0` (commit
  `c240f9c`, which resolves the draft by its numeric release identity);
  `v0.4.0` is the first release run to exercise it.
