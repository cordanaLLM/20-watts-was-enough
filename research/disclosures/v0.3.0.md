## Pre-release evidence and publication conditions

The redesigned Pages portal and focused reader were inspected locally at
`1440`, `390` and `320` CSS-pixel widths. The inspection covered line measure,
title-preserving navigation, wrapping and horizontal overflow. A separate
headless-browser regression now requires every Mermaid wrapper to retain one
non-empty SVG after React's development StrictMode effect cycle. These are
interface and rendering checks, not reader-comprehension or accessibility-
conformance results.

The last already-published `origin/main` aggregate evidence available while
this record was drafted is bound to commit
`177173286b216ce05b16865109614a156dad29e5`. It does not verify the later
`v0.3.0` candidate edits. Source-level tests exercise stable file reads,
translation manifests, release-image admission, tag attachment, current-build
attestation and rejection of missing existing-image provenance,
repository-label reconciliation and runtime numerical identity, but a
passing simulated case is not evidence that the corresponding remote release
operation occurred.

Publication requires the aggregate gate, an observed-complete deterministic
tag-bound PDF, checksum and attestation verification, and offline execution of
every admitted OCI digest to pass on the exact tag. The release workflow must
record the tag, commit, run identity, PDF digest and observed diagram count,
asset checksums and final OCI digests. This source disclosure does not claim
that those post-tag checks have completed. It also does not claim that the
three first-use GHCR packages are public until unauthenticated exact-digest
pulls pass with an empty Docker configuration. Those checks establish a
reproducible publication boundary; they do not create a scientific result or
an independent review.
