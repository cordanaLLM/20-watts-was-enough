# 0093 — Refuse tool attribution in commit messages

- **Status:** accepted
- **Date:** 2026-10-11
- **Decided by:** the maintainer's ruling of 2026-10-11 on attribution lines in
  commit history, recorded as `fleet-attribution-leak-20261011` (paraphrased):
  a squash body is written by hand, the commit messages of a pull request are
  read before the merge, and each repository carries a commit-message check
  that refuses a tool co-author trailer and is shown refusing a planted one.
  No session rewrites history; what happens to the existing lines is decided
  once for all repositories.
- **Authority:** `tooling/internal/ciplan/commit_messages.go`, the `messages`
  subcommand in `tooling/internal/ciplancli/`, the fourth step of the
  `impact-plan` job in `.github/workflows/ci.yml` and its rule in
  `scripts/validate-engineering-policy.mjs`. No claim, principle or status
  changes.
- **Related:** [0075](0075-isolate-ci-driver-dependency-closures.md),
  [0088](0088-impact-scope-ci-and-local-validation.md)

## Context

On 2026-10-11 the 331 commits of `main` at `92ce120` held 76
`Co-authored-by` lines in 62 commits. All 76 name a tool: 74 carry one of
three model names with the address `noreply@anthropic.com`, and two name the
code-scanning autofix bot. None names a person.

The [research-integrity baseline](../research/research-integrity-baseline.md)
ties authorship to a substantial contribution, review, approval and
accountability, and says that tool use alone does not create it. It asks for
material tool use to be disclosed with its purpose, its version and the human
check. A co-author trailer does the first thing the baseline rules out and
none of what it asks for.

A squash merge can carry such a line to `main` without anyone typing it. The
repository's squash setting (`COMMIT_MESSAGES`, read on 2026-10-11) proposes
the pull request's commit messages as the squash body, so a trailer in one
branch commit lands on `main` unless the person who merges replaces the body.

## Decision

1. `20w ci messages`, and the same adapter in the private `ci-plan` driver,
   refuses two kinds of line in a commit message:
   - a `Co-authored-by` trailer whose address ends in `@anthropic.com`, or
     whose name contains `Claude` followed by `Opus`, `Sonnet`, `Haiku`,
     `Fable` or `Code`, or contains `Copilot`, `Codex`, `ChatGPT` or `Gemini`;
   - a line that begins, after any symbols, with `Generated with` or
     `Generated by` and one of those tool names.
2. The `impact-plan` job runs the check on every CI event. For a pull request
   it reads the commits that the head reaches and the base tip does not; the
   base tip is the first parent of the test merge commit. For a push to
   `main` it reads the commits between the previous and the new tip. Any other
   event, and a push without a usable previous tip, reads the tip commit alone
   and says so in a notice.
3. The check never reads a commit that the base already reaches. The 76
   existing lines stay, and this change rewrites nothing.
4. Before a squash merge the person who merges writes the body and may check
   it first: `go -C tooling run ./cmd/20w ci messages --message-file <file>`.
5. Material tool use is still disclosed in the pull request and, for a
   research output, under `research/disclosures/`. The check reads trailers
   and footers only; prose that names a tool passes.
6. A further tool name is a reviewed edit of the pattern together with a
   refused case in `commit_messages_test.go`.

## Consequences

- A pull request with such a line in any of its commits fails `CI success`
  until the commit message is reworded on the branch. This includes a commit
  made by the code-scanning autofix, whose trailer accounts for two of the 76
  lines.
- A squash body is written at merge time, after the pull-request run. A
  trailer typed there is found by the push run on `main`, which then fails in
  `impact-plan` before any lane starts. The check reports the commit and the
  line; it repairs nothing, and the next push is judged on its own commits.
- A range of more than 512 commits, a message above 64 KiB, Git output above
  4 MiB or a Git call longer than 15 seconds fails the check instead of being
  read in part.
- The check does not see a tool it has no name for, a trailer with another
  key, or text in a pull-request body.

## Alternatives considered

- **Check in the pull-request title workflow.** That job reads the title from
  the event and checks out nothing. It would also never see a push to `main`.
- **A local commit-message hook.** A hook exists per clone, and the squash
  body is written on the forge.
- **Refuse every co-author trailer.** People who wrote part of a change are
  credited this way.
- **Refuse every bot address.** The history holds no such line beside the
  autofix trailer, so the wider rule has no measured case.
- **Remove the 76 lines from history.** That rewrites every commit of `main`
  after the first affected one; it is outside this change.

## Verification and disclosure

Run against `main` at `92ce120` from the root commit, the check refuses 76
lines, which equals an independent `git log | grep` count; the four distinct
trailer values are the refused cases of the Go test. The tip commit alone
passes. Two prose sentences in the history that contain `generated by` and
`regenerated with` pass, as intended.

The workflow step was extracted from `ci.yml` and run in a scratch clone for
eight events: a clean pull request (exit 0), a pull request with a planted
trailer in the second of three commits (exit 1, that commit and line named), a
merge commit that does not merge the stated head (exit 1), a push whose squash
body carries a generated-with footer (exit 1), the push after it (exit 0), a
push without a previous tip and a forced push (tip only, exit 0), and a manual
run on the offending tip (exit 1).

`npm run validate:policy` fails with one finding on the workflow without the
step. The policy test weakens the step in seventeen ways, removes it and
moves it before the plan step, and expects that finding each time.

AI assistance wrote the change, the tests and this record. The runs named
above verified the result; the maintainer decided the rule.
