# Maintainers

This file records repository stewardship. It does not confer scientific status
on a claim or result, and it does not prove that a GitHub permission or branch
rule is enabled.

## Current maintainer

### [`@lusoris`](https://github.com/lusoris)

Maintainer for project scope, merges, releases, security handling, research
and experiment authority review, licensing, and host settings. The repository
belongs to the [`cordanaLLM`](https://github.com/cordanaLLM) organization, in
which `@lusoris` holds the organization and repository admin roles.

## Responsibilities

The maintainer is responsible for:

- preserving the canonical Git history, append-only decisions, and source
  provenance;
- enforcing the distinction between observations, translations, hypotheses,
  development artifacts, confirmation evidence, and results;
- reviewing claim and principle changes, evidence-status promotion, protocol
  versions, and experiment authority against their registered contracts;
- recording contributor roles, support, competing interests, material tool use,
  triggered ethics or misuse review, and research-object stewardship under the
  [`research integrity baseline`](research/research-integrity-baseline.md);
- keeping generated sites, the downloadable PDF and manifest, licences, and
  third-party notices tied to the canonical source state;
- handling vulnerability reports without exposing confidential details;
- maintaining contribution, support, governance, and conduct processes; and
- verifying repository-host settings before relying on them.

The maintainer may reject an in-scope-looking change when its evidence,
provenance, reuse rights, null model, reproducibility, security, or maintenance
cost is inadequate. The rationale should be stated in the issue, pull request,
or decision record.

## Ownership and review routing

[`CODEOWNERS`](.github/CODEOWNERS) maps repository paths to `@lusoris` for
review routing. It is an ownership declaration, not proof that GitHub enforces
approval or branch protection.

Direct-maintainer and pull-request changes follow
[`GOVERNANCE.md`](GOVERNANCE.md). Merge authority never overrides scientific
promotion gates or licensing boundaries.

## Changing maintainership

Adding, removing, or materially changing a maintainer's authority requires an
accepted decision record. The same change updates this file and
[`CODEOWNERS`](.github/CODEOWNERS). Access granted in GitHub must be verified
separately; editing these files does not grant permissions.
